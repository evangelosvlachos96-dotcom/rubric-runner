# Architectural Note

CodeJudge uses Clean Architecture — four projects with compiler-enforced inward dependencies — but deliberately omits CQRS, MediatR and generic repositories: four endpoints do not justify the ceremony, and the design documents record every alternative considered. The `submissions` table doubles as the job queue: inserting a row is the enqueue, so accepting and scheduling a submission is one atomic write, and a `BackgroundService` claims work with PostgreSQL `FOR UPDATE SKIP LOCKED`. Hangfire and in-memory channels lost on dual-write and durability. Evaluation is an ordered, short-circuiting rubric (Security → Compiles → Test) over a problem catalog, executed through a language-agnostic JSON harness, so adding a language is one evaluator plus one script. Assumptions: a static API key suffices, so `userId` is client-asserted; the keyword scan is a rubric item, not a security boundary; C# runs in-process and Python/JavaScript in child processes — real isolation needs a containerised runner, the documented next step.
