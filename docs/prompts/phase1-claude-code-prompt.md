## Solution structure (Clean Architecture, 4 projects + 2 test projects)

Follow the exact layout in System Design §5.4. Project references: `Api → Application, Infrastructure`; `Infrastructure → Application`; `Application → Domain`; `Domain → nothing`. `Api` and `Infrastructure` must not reference each other. Composition via `AddApplication()` in Application and `AddInfrastructure(IConfiguration)` in Infrastructure.

### CodeJudge.Domain (no NuGet packages)
- Enums: `Language { CSharp, Python, JavaScript }`, `SubmissionStatus { Pending, Evaluating, Completed, Error }`, `RubricItem { Security, Compiles, Test }`.
- `Submission` aggregate root — private setters, static `Create(userId, problemId, language, code)`, methods `Claim(string workerId, DateTime lockUntil)`, `Complete(IEnumerable<EvaluationResult> results)`, `Fail(string message)` exactly as specified in Database Design §4 (guards, timestamps, `AttemptCount`, `InvalidStatusTransitionException`). `Id = Guid.CreateVersion7()`. Navigation `IReadOnlyCollection<EvaluationResult> Results`.
- `EvaluationResult` — `Id`, `SubmissionId`, `RubricItem`, `Passed`, `Skipped`, `Message`, `Output` (string, JSON), `TestsPassed?`, `TestsTotal?`, `DurationMs?`, `EvaluatedAt`. Static factories `Passed(...)`, `Failed(...)`, `SkippedResult(item)`.
- Exceptions: `DomainException` (base), `InvalidStatusTransitionException`, `UnsupportedLanguageException`.

### CodeJudge.Application

- `Common/NotFoundException.cs`, `Common/PagedResult<T>` (`Items, Page, PageSize, TotalCount, TotalPages`).
- `Abstractions/`: `ISubmissionRepository` (`AddAsync`, `GetByIdWithResultsAsync`, `GetPagedByUserAsync`), `IUnitOfWork` (`SaveChangesAsync`), `ISubmissionClaimer` (`ClaimBatchAsync(int batchSize, string workerId, TimeSpan lockDuration, CancellationToken)`), `ICodeEvaluator` (`Language Language; Task<CompileResult> CompileAsync(string code, CancellationToken); Task<HarnessRunResult> RunAsync(string code, ProblemDefinition problem, CancellationToken)`), `IProblemCatalog` (`IReadOnlyList<ProblemDefinition> GetAll(); ProblemDefinition? Find(string id); bool Exists(string id)`), `IRestrictedKeywordPolicy` (`RestrictedKeywordMatch? Check(Language, string code)`).
- `Problems/`: `ProblemDefinition(Id, Title, Description, Difficulty, IReadOnlyDictionary<Language, LanguageSignature> Signatures, IReadOnlyList<TestCase> Cases)`, `LanguageSignature(FunctionName, SignatureText)`, `TestCase(Id, JsonElement[] Args, JsonElement Expected, bool IsSample)`. `ProblemCatalog : IProblemCatalog` with the four problems from System Design §6.5 (`sum-two-numbers`, `reverse-words`, `balanced-brackets`, `two-sum`) with all listed test cases. Store args/expected as JSON so they are language-neutral.
- `Evaluation/`: `CompileResult(bool Success, IReadOnlyList<CompileDiagnostic> Diagnostics, int DurationMs)`, `TestCaseResult(int Id, JsonElement Expected, JsonElement? Actual, bool Passed, string? Error, double DurationMs)`, `HarnessRunResult(IReadOnlyList<TestCaseResult> Cases, bool TimedOut, string? Stderr, int DurationMs)`, `EvaluationService` that runs the rubric in order Security → Compiles → Test, short-circuits, always produces exactly three `EvaluationResult`s (skipped ones flagged), serialises diagnostics / cases into `Output` JSON, sets `TestsPassed/TestsTotal/DurationMs`. Evaluators are resolved via `IEnumerable<ICodeEvaluator>` → dictionary by `Language`.
- `Submissions/`: DTOs `SubmissionDto` (id, userId, problemId, language, status, createdAt, startedAt, completedAt, errorMessage, results: `EvaluationResultDto[]`), `EvaluationResultDto`, `SubmissionSummaryDto`, `ProblemDto`; `ISubmissionService` / `SubmissionService` (`CreateAsync`, `GetAsync` → throws `NotFoundException`, `GetByUserAsync(userId, page, pageSize)`); `Validators/CreateSubmissionRequestValidator` (FluentValidation): userId required ≤100 and pattern `^[A-Za-z0-9_\-.@]+$`, problemId required and `IProblemCatalog.Exists`, language must be a defined enum value, code required and ≤ 65536 chars. The validator lives in Application and validates an Application-level `CreateSubmissionCommand` record (userId, problemId, language, code).
- `DependencyInjection.AddApplication()` registers services, `IProblemCatalog` singleton, validators via `AddValidatorsFromAssemblyContaining`.

### CodeJudge.Infrastructure
Packages: `Npgsql.EntityFrameworkCore.PostgreSQL`, `EFCore.NamingConventions`, `Microsoft.EntityFrameworkCore.Design`, `Microsoft.CodeAnalysis.CSharp`, `Microsoft.Extensions.Hosting.Abstractions`.
- `Persistence/CodeJudgeDbContext` with `UseSnakeCaseNamingConvention()`; `IEntityTypeConfiguration` for both entities exactly per Database Design §6 and §10: enums `HasConversion<string>()` + check constraints, `text` for code, `jsonb` column type for `output`, `timestamptz`, cascade delete, unique index `(submission_id, rubric_item)`, partial index `ix_submissions_queue` on `(status, locked_until, created_at)` with filter `status IN ('Pending','Evaluating')`, index `(user_id, created_at DESC)` with `IncludeProperties(problem_id, language, status)`, check constraint on `tests_passed <= tests_total`. `DbContext` implements `IUnitOfWork`.
- `Persistence/Repositories/SubmissionRepository`.
- `Persistence/SubmissionClaimer` implementing the CTE + `UPDATE … RETURNING` claim query from Database Design §8 with `Database.SqlQueryRaw<Submission>` (or `FromSqlRaw` on the set), parameterised.
- Generate the initial migration `InitialCreate` (`dotnet ef migrations add InitialCreate --project src/CodeJudge.Infrastructure --startup-project src/CodeJudge.Api`). On startup in Development, apply migrations automatically (`MigrateAsync`), guarded by config `Database:ApplyMigrationsOnStartup`.
- `Security/RestrictedKeywordPolicy` — per-language keyword list bound from configuration `Security:RestrictedKeywords:{Language}` with the defaults from System Design §6.6; returns the first matched keyword and its line number.
- `Evaluators/` — create `CSharpEvaluator`, `PythonEvaluator`, `JavaScriptEvaluator`, `ProcessRunner` (start process, feed stdin, capture stdout/stderr, timeout with `Kill(entireProcessTree: true)`), and embedded resources `Harness/harness.py` and `Harness/harness.js` implementing the JSON protocol in System Design §6.5. **Phase 1 scope:** implement `ProcessRunner` and the harness scripts fully; implement `CompileAsync` for all three (Roslyn compile; `python -c "import ast,sys; ast.parse(sys.stdin.read())"`; `node --check`); implement `RunAsync` for Python and JavaScript fully; for C#, implement `RunAsync` with Roslyn + collectible `AssemblyLoadContext` + reflection + `Task.WaitAsync(timeout)` — if this becomes complex, leave a clearly marked `// TODO(phase-2)` with the compile path working and `RunAsync` returning a `HarnessRunResult` whose single case has `Error = "C# execution not implemented yet"`.
- `Workers/EvaluationSettings` (PollingIntervalSeconds=2, BatchSize=5, LockDurationSeconds=90, CompileTimeoutSeconds=10, RunTimeoutSeconds=5, MaxAttempts=3) bound from `Evaluation` section with `ValidateDataAnnotations().ValidateOnStart()`.
- `Workers/EvaluationWorker : BackgroundService` — loop per System Design §6.4 / Database Design §8: claim batch via `ISubmissionClaimer` in a scoped `IServiceScope`, for each row: if `AttemptCount > MaxAttempts` → `Fail`; else run `EvaluationService`, `Complete`, `SaveChangesAsync`; try/catch per item → `Fail(ex.Message)` and continue; log with `SubmissionId` and `WorkerId` scope; `WorkerId = $"{Environment.MachineName}:{Environment.ProcessId}:{Guid.NewGuid():N}"`; honour `stoppingToken`; delay `PollingIntervalSeconds` when the batch is empty.
- `DependencyInjection.AddInfrastructure(IConfiguration)` registers DbContext (connection string `ConnectionStrings:DefaultConnection`), repositories, claimer, evaluators, keyword policy, settings, hosted worker.

### CodeJudge.Api
Packages: `Asp.Versioning.Mvc`, `Asp.Versioning.Mvc.ApiExplorer`, `Swashbuckle.AspNetCore`, `Serilog.AspNetCore`, `Serilog.Sinks.Console`, `AspNetCore.HealthChecks.NpgSql`, `FluentValidation`.
- `Models/Common/ApiResult<TData>` — **exactly** this shape and behaviour: properties `Status` (bool), `Description` (string?), `Data` (TData?), `Error` (`ErrorDetails? { CodeJudgeErrorCode ErrorCode; string? Description }`); success ctor `ApiResult(TData data, string? description = "🚀 Houston, we don't have a problem")`; failure ctor `ApiResult(CodeJudgeErrorCode code, string? description = "🔥 Houston, we have a problem")`.
- `Models/Requests/CreateSubmissionRequest` (userId, problemId, language as `Language` enum, code) with XML docs and `[SwaggerSchema]`-friendly examples.
- `Controllers/V1/SubmissionsController` — `[Authorize] [ApiController] [ApiVersion("1.0")] [Route("api/v{version:apiVersion}/[controller]")] [Produces("application/json")]`, constructor-injected `ISubmissionService` (no MediatR — this is a documented decision), XML `<summary>`/`<response>` docs on every action, `[ProducesResponseType(typeof(ApiResult<…>), StatusCodes.…)]` for every possible status. Actions: `POST` → `CreatedAtAction(nameof(GetById), new { id, version = "1.0" }, new ApiResult<SubmissionDto>(dto, "Submission accepted and queued for evaluation."))`; `GET {id:guid}` → `Ok(new ApiResult<SubmissionDto>(dto))`; `NotFoundException` is thrown by the service and mapped by middleware.
- `Controllers/V1/UsersController` — `GET {userId}/submissions?page=1&pageSize=20` → `ApiResult<PagedResult<SubmissionSummaryDto>>`; validate page ≥ 1 and 1 ≤ pageSize ≤ 100 (return 400 `ValidationFailed` via `ValidationException`).
- `Controllers/V1/ProblemsController` — `GET` → `ApiResult<IReadOnlyList<ProblemDto>>` (id, title, description, difficulty, signatures per language, the sample cases only).
- `Middleware/ExceptionMiddleware` — same structure and logging behaviour as this reference, adapted to our exceptions and error codes:
  - `ValidationException` → 400 / `ValidationFailed`, message = errors joined with `" | "`; but if any error has `ErrorCode == nameof(CodeJudgeErrorCode.ProblemNotFound)` / `UnsupportedLanguage` / `CodeTooLarge` (set via FluentValidation `.WithErrorCode(...)`), use that specific code instead.
  - `NotFoundException` → 404 / `SubmissionNotFound` when the exception's `EntityName == "Submission"`, else `NotFound`.
  - `InvalidStatusTransitionException` → 409 / `Conflict`.
  - `UnsupportedLanguageException` → 400 / `UnsupportedLanguage`.
  - `DomainException` → 400 / `ValidationFailed`.
  - anything else → 500 / `Unknown` with the safe message; `LogError` with `TraceId`; 4xx → `LogWarning`.
  - Serialise with `JsonSerializerOptions { PropertyNamingPolicy = CamelCase, Converters = { new JsonStringEnumConverter(JsonNamingPolicy.CamelCase) } }`.
- `Filters/ValidationActionFilter : IAsyncActionFilter` — for each action argument, resolve `IValidator<T>` from DI (the request type maps to the command validator via a small `CreateSubmissionRequest → CreateSubmissionCommand` mapping, or register a request-level validator that delegates); throw `ValidationException` on failure. Register globally via `AddControllers(o => o.Filters.Add<ValidationActionFilter>())`. Disable the built-in `[ApiController]` model-state 400 (`SuppressModelStateInvalidFilter = true`) so **all** 400s go through our middleware and come out as `ApiResult`.
- `Authentication/ApiKeyAuthenticationHandler : AuthenticationHandler<ApiKeyOptions>` — scheme `"ApiKey"`, header `X-Api-Key`, key from `ApiKeySettings:Key`; constant-time comparison; `HandleChallengeAsync` writes 401 with `ApiResult<object>(CodeJudgeErrorCode.Unauthorized, "Missing or invalid API key.")`. Make it the default scheme; `[Authorize]` on all controllers; `/health` and Swagger anonymous.
- `Swagger/` — Swashbuckle with API-version grouping (one doc per version via `IApiVersionDescriptionProvider`), XML comments, `ApiKey` security definition + requirement filter, `JsonStringEnumConverter` respected so enums show as `pending | evaluating | …`.
- `Program.cs` — Serilog (console, request logging), `AddApplication()`, `AddInfrastructure()`, controllers with `JsonStringEnumConverter(JsonNamingPolicy.CamelCase)` in `JsonOptions`, API versioning (default 1.0, `UrlSegmentApiVersionReader`, report versions), health checks with `AddNpgSql`, `UseMiddleware<ExceptionMiddleware>()` first, then Serilog request logging, Swagger, auth, controllers, `MapHealthChecks("/health").AllowAnonymous()`.
- `appsettings.json` + `appsettings.Development.json` with `ConnectionStrings:DefaultConnection = "Host=localhost;Port=5432;Database=codejudge;Username=postgres;Password=postgres"`, `ApiKeySettings:Key = "dev-api-key-change-me"`, `Evaluation`, `Security:RestrictedKeywords`, `Database:ApplyMigrationsOnStartup = true`, Serilog config.
